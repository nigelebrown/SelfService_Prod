# Local break-glass administrator runbook

The local administrator is an emergency path for the **internal administration application**, not an alternate Active Directory account and not a DMZ credential. Routine administrators must use AD group-based authorization.

## Credential custody

The account requires both a random generated password and a TOTP authenticator. Store the two factors separately under the organization's emergency-access custody process. Do not place both in the same password document, ticket, chat or envelope. Limit knowledge/access to specifically authorized custodians.

Only an AD Platform Administrator can create/rotate, unblock or disable the local account. The break-glass account cannot rotate itself. Its password is stored only as a salted/peppered verifier; its TOTP secret is protected by the Internal Service Data Protection key ring.

## Use procedure

1. Declare the reason for emergency use and create/record an incident/change reference outside the application.
2. Access the internal admin URL from an authorized management network/workstation only.
3. Authenticate with local username + generated password + current TOTP.
4. Perform the minimum required recovery activity.
5. Review the audit/SOC event generated by use of the local identity.
6. As soon as AD administrative access is restored, an AD Platform Administrator rotates the break-glass password **and TOTP seed**, tests the new custody material, and invalidates the previous material.

Rotate at a defined regular interval even if unused (recommended at least quarterly) and immediately after any use, suspected disclosure or custodian change. Test the emergency procedure in the non-production environment.
